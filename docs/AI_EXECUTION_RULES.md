# 团队 AI 执行准则

人和 AI 每次开发都按下面的顺序做。核心要求：**执行前重新拉项目记忆。**

拉 Git 几乎不耗模型 token。真正耗用量的是读代码和改代码。先把远端和记忆文件拉到最新，再决定要打开哪些文件，避免在过期事实上来回改。

## 顺序

1. **拉最新代码。** 执行 `git fetch`，检出要改的目标分支，再 `git pull`。一次做完的等价操作也可以，例如 `git fetch origin` 之后 `git switch` 到已跟踪远端、并能快进的分支。从 `main` 新开功能分支时，先把本地 `main` 更新到 `origin/main`，再从那一点开分支。
2. **读最新记忆。** 阅读本仓这次拉取之后的 `docs/PROJECT_MEMORY.md` 和本文件 `docs/AI_EXECUTION_RULES.md`。以文件里的文字为准，不要沿用对话里更早的复述。
3. **再开始改代码。** 上面两步做完才改。范围停在当前任务里。`docs/PROJECT_MEMORY.md` 标成未做的能力，不要写成已经有。
4. **改完再推，优先开 PR。** 推到功能分支，优先开 PR 合入 `main`。不要直接推 `main`。
5. **事实变了就改记忆。** 若这次改了产品事实或协作约定，同步更新 `docs/PROJECT_MEMORY.md`，并和代码放在同一个 PR 里提交。

## 和代码的关系

`docs/PROJECT_MEMORY.md` 记录当前约定。实现细节以代码和根目录 `README.md` 为准。两边不一致时，先看最新提交，再在同一个 PR 里把记忆改清楚。
